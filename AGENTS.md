# Repository Guidelines

## Project Overview

`glkvm` is a Bun/TypeScript CLI for GL.iNet KVM-over-IP devices (Comet/GL-RM, PiKVM-compatible `kvmd` HTTP API). It takes snapshots, sends keystrokes/shortcuts/text, selects KVM-switch ports, and drives ATX power. Tested on Comet RM4PE fw V1.10.1 (kvmd/uStreamer 6.37).

## Architecture & Data Flow

```
argv → run() → parseArgs → COMMANDS[cmd] handler (validates, returns Action)
     → loadConfig() → new Kvm(cfg) → await action(kvm) → JSON/bytes to stdout
```

- **Two-phase commands** (`src/cli.ts`): `Handler = (rest, flags, io) => Action`, `Action = (kvm) => Promise<void>`. Each handler runs its own argument checks **before** returning the `Action`, so its `usageError(...)` (exit 2) fires before config loading or network access. CI checks this: with no config present, `./dist/glkvm key 'Bad Key'` must exit 2.
- **Entry gate**: `if (import.meta.main)` runs `run(Bun.argv.slice(2))`. A `CliError` supplies the message and exit code; every other failure exits 1. Only exit-2 `CliError`s get the "Run `glkvm help`" hint.
- **Flag parsing is permissive**: `node:util` `parseArgs` with `strict: false` and `allowPositionals: true`; only `--delay` and `--port` are declared (as strings). Unknown flags and some extra positionals are silently ignored, so there is no global validation. Each command checks the flags it uses; for example, `atx click`/`atx power` require `--yes`, and `--port` on `atx power` is a usage error.
- **Client** (`src/client.ts`, class `Kvm`):
  - `request()` returns the raw `Response`.
  - `call()` unwraps kvmd's `{ok, result}` envelope and throws `CliError` with `result.error_msg` when `ok` is false.
  - `snapshot()` returns `Uint8Array` JPEG bytes.
  - Requests use the `Cookie: auth_token=…` header, `AbortSignal.timeout` (default 15 s), and the Bun-specific `tls: { rejectUnauthorized: !cfg.insecure }`.
- **Auth**: `POST /api/auth/login` sends form fields `user`/`passwd` and gets an `auth_token` cookie. Tokens live under `${XDG_CACHE_HOME:-~/.cache}/glkvm-cli/`, in a file named after `URL.host` (port included), with characters outside `[\w.-]` replaced by `_`. New cache directories are created 0700 (an existing directory is not chmodded); the token file is chmodded to 0600 after every write. The file's first line is a SHA-256 of `baseUrl\0user\0pass`, so a token saved under old credentials is ignored. The client logs in lazily and logs in again once on a 401/403.
- **Snapshot quirk**: the streamer only runs while a client holds `/api/ws?stream=1` open. After logging in, `snapshot()` opens that WebSocket and polls `/api/streamer/snapshot` until it gets HTTP 200 with `image/*`; a 503 means the stream is still warming up. Polling has a 20 s deadline, checked only between polls, and each poll has its own 10 s timeout, so a call can run past 20 s. The socket is closed in `finally`. OCR was broken on the tested firmware, so it is deliberately not exposed.

## Key Directories

- `src/`: all source. Ships as-is (`files: ["src"]`, `bin.glkvm = src/cli.ts`) because Bun runs TS directly.
- `test/`: `<module>.test.ts` files that mirror `src/<module>.ts`.
- `.github/workflows/ci.yml`: CI. `.vite-hooks/`: git hooks generated by `vp config`. Do not hand-edit `.vite-hooks/_/`.
- `dist/`: output of the compiled binary (gitignored).

```sh
vp install            # canonical install (bun install also works); runs `vp config` hooks via prepare
vp check              # oxfmt + oxlint + type-aware typecheck (no separate tsc/eslint/prettier)
vp check --fix        # autofix
vpr test              # all tests (vp run → bun test; never `vp test`, that is Vitest)
vpr test test/cli.test.ts     # one file
vpr test -t "expandKeys"      # by name

./dist/glkvm help     # smoke the binary
bun src/cli.ts status # run from source (needs KVM_* config)
```

## Code Conventions & Common Patterns

- **Errors**: use only `CliError` (`src/errors.ts`), whose `exitCode` is `1 | 2`. Exit 1 means a device or config failure. Exit 2 means a bad invocation; create it with `usageError(msg)`. Do not call `process.exit` outside the entry gate.
- **Config** (`src/config.ts`): `loadConfig(env = process.env)` is the DI seam for env. Precedence is env vars first, then the env file (`KVM_ENV_FILE`, default `~/.config/glkvm.env`, optional). Required vars are `KVM_HOST`, `KVM_USER`, `KVM_PASS`. Missing vars produce one error that lists all of them. `KVM_INSECURE` is checked with a truthy lookup.
- **Custom env parser is deliberate** (`parseEnvFile`): it supports an optional `export ` prefix, whole-line `#` comments, and matching surrounding single/double quotes, and it rejects unbalanced quotes. A `#` inside a value is literal: `KVM_PASS=secret # note` makes the whole suffix part of the password. There are no inline comments, escapes, or interpolation. Do not replace it with dotenv or a stdlib parser, because those truncate passwords that contain `#`.
- **Type guards**: shared guards live in `src/guards.ts` (`isRecord`). Do not inline them in client code. Parsed device JSON stays `unknown` until a guard checks it.
- **Lookup tables**: fixed tables use `Record<string, true>` (e.g. `ATX_BUTTONS`, `ATX_ACTIONS`, `TRUTHY`). Use `Set` only for collections that change at runtime.
- **Output**: JSON goes through `io.print` (`JSON.stringify(…, null, 2)`). Handlers receive the `Io` object (`{ out, print }`), and `run(argv, out)` accepts an output stream. Current CLI tests only cover usage errors, not successful command output.
- **New commands**: add an entry to `COMMANDS` in `src/cli.ts`, then update `USAGE` (printed as-is by `help`) and the README command table, which is maintained separately. Check the command's arguments before returning the `Action`.
- **TS strictness**: `strict` and `noUncheckedIndexedAccess` are on, so indexing yields `T | undefined`. `verbatimModuleSyntax` is on, so type-only imports must use `import type`. `module: Preserve` with bundler resolution.
- **Style**: Ultracite oxfmt/oxlint presets. Object literal keys are sorted alphabetically. Prefer Bun APIs (`Bun.file`, `Bun.sleep`, `Bun.serve`) and `node:` specifiers for builtins.

## Important Files

- `src/cli.ts` is the entry point; its `USAGE` constant is the runtime help text.
- `vite.config.ts` holds the `fmt`/`lint` config (typeAware and typeCheck on, `vite-plus/prefer-vite-plus-imports: error`) and the `staged` hook mapping.
- `package.json`: `vite` is aliased to `@voidzero-dev/vite-plus-core` in both `devDependencies` and `overrides`; keep the two in sync when updating dependencies. Read it for current Bun and tool versions.

## Runtime/Tooling Preferences

- **Bun only**: no Node target. Tests use `bun:test`, never vitest or `node:test`.
- Tooling is Vite+ (`vp`) plus Ultracite. Do not add eslint, prettier, or a `tsc` script.
- Pre-commit runs `vp staged`, which runs `vp check --fix` on staged files and `actionlint` on workflow YAML (needs `actionlint` on PATH). `VP_GIT_HOOKS=0` disables it.
- CI pins actions by SHA. Keep that, and keep `persist-credentials: false`. Dependabot runs weekly for actions and bun dev deps.
- Never commit `*.env` or `.env*` files, or `snapshot-*.jpg` files (all gitignored).

## Testing & QA

- Run `vpr test` for the suite or `vpr test --coverage` for a coverage report; no coverage threshold is configured.
- **Tests must never contact a real KVM**, since commands can cut host power or send keystrokes. Test new commands with a usage-error case (fails before config/network) and a behavior case against the local fake server with a temporary `tokenFile`. Without an explicit `tokenFile`, `Kvm` writes to the user's real token cache.
- **HTTP is faked with a real server, not mocks.** `test/client.test.ts` starts `Bun.serve({ port: 0 })` on 127.0.0.1 as a fake kvmd and stops it in `afterAll`. No `mock()`/`spyOn`, no snapshots, no fixture directories.
- To inject env, pass an object literal to `loadConfig`. `test/cli.test.ts` is the exception: it sets `KVM_ENV_FILE=/nonexistent/...` and deletes `KVM_HOST` to prove that usage errors fire before config or network.
- Temp files use `os.tmpdir()/glkvm-test-${process.pid}.<ext>` and are removed with `rmSync(…, { force: true })`.
- To assert an error, capture it as `unknown` first: `const failure: unknown = await fn().catch((e: unknown) => e)`. Then use `toBeInstanceOf(CliError)` or check `exitCode`.
- Test names are lowercase behavior sentences. Use `describe` only for units with several tests.
- Before pushing, run `vp check && vpr test && vpr build && ./dist/glkvm help`.
